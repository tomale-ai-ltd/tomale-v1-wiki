## What I actually did

- Created [[image-generation-flow]], a full Mermaid diagram of the pipeline (orchestrator queue → worker tick recovery/throttle/drain → claim → three async executors), correcting during drafting how `error_retry` vs `error_terminal` and the cover-image job queuing actually work.
- Created a decision note (now on disk at `Project/Decisions/defer-image-pipeline-throughput-to-phase-2.md`) recording that image generation throughput (10–15 min/story) is deferred to Phase 2 (off-Xano pipeline as part of the Bedrock migration) — Phase 1 scope is correctness only.
- Root-caused duplicate executor runs to five compounding bugs, fixed in order: (1) `claim_image_jobs` wrote `locked_until` as epoch because the lease-seconds env var wasn't cast to int, making every job permanently re-claimable; (2) claim-time lease was hardcoded to 180s, far short of the ~700s claim-to-start gap; (3) the reaper had no grace period and requeued jobs still legitimately waiting in the async queue — added `image_reaper_grace_seconds` (300s); (4) the reaper was incrementing `attempt` on recovery, not just on genuine claims, prematurely pushing slow-but-healthy jobs toward terminal; (5) the real structural bug — success/error handling in all three executors was nested inside `if (compiler_status == 200)`, so a compiler failure (e.g. 429) left the job permanently stuck in `processing` until the reaper requeued it, producing a second run next tick. Compounded by error branches referencing the out-of-scope `$exec.result` instead of `$result`.
- Restructured all three executors (`executor_page_image`, `executor_cover_image`, `executor_character_image`) so terminal state is always written outside the compiler conditional: `$result` seeds retryable, an `$image_called` flag guards references to the image response, a single terminal conditional (success → retryable → terminal) closes every path, and `api_request`/`api_response` are whitelisted with an `$api_log` variable for compiler-stage failures. Added `simulate_compiler_error` / `simulate_image_error` test inputs (default false) to exercise failure paths without hitting OpenAI or touching production behavior.
- Per executor: fixed a leftover success-path `error_message` bug in `executor_page_image`; confirmed `executor_cover_image`'s happy path and both simulated errors; confirmed `characters.cover_image` is the correct (if oddly named) field in `executor_character_image` and fixed its terminal branch, which had previously set retry fields on a terminal failure.
- Found and fixed a late regression: `simulate_*` inputs weren't set as defaults on the page/cover executors, so when not explicitly passed through async dispatch, `executor_runs` records were never created and the run failed at the lookup step. Fixed the input handling; a fully clean run is not yet confirmed.
