## What I actually did

**Variables and auth (partly via Postman agent, rest by hand):**
- Added collection variables for story/character test data (`storyTitle`, `storySubtitle`, `storyUserPrompt`, `themeId`, `artworkStyleId`, `totalPages`, `characterName`, `characterDescription`). API field is `user_prompt`, not `synopsis`.
- Folder 3 requests were using an unresolved `{{baseUrl}}`; confirmed the `app` API group (`auth_base_url`) contains everything needed and switched them over.
- Added `webhookUrl` (webhooks API group), `stripe_webhook_secret` (secret type), and `test_account_email_user2` / `test_account_password_user2` to the environment.
- New sub-folder `3A-NEG · User 2 auth`: **NEG-1A** `POST /auth/login` (user2) sets `bearerToken_user2` only; **NEG-1B** `GET /auth/me` (user2) uses Bearer `{{bearerToken_user2}}` and asserts the token belongs to user2. Neither touches `bearerToken` or `users_id`. Confirmed no collection- or folder-level scripts in `_tests` that could leak into them (the `app` and `webhooks` collections have their own collection-level `pm.sendRequest` scripts, irrelevant to `_tests`).
- `3A-1` (create `store_orders`) given a post-response script that sets `orderId`.
- `3A-3` (`create_checkout_session`) was missing its inputs — now sends `store_orders_id` and `shipping_option_id`.

**Payment hop automated (3B-2, was A4 manual gate):**
- Rewritten as `POST {{webhookUrl}}/stripe/webhook_payment_confirmation`. Pre-request script builds a `checkout.session.completed` event for `{{checkoutSessionId}}` (unique `evt_test_…` id per run because the webhook dedups), signs it with HMAC-SHA256 over `t.payload` using `stripe_webhook_secret`, and sends it raw with a `Stripe-Signature` header. Post-response asserts 200.
- Sample real payload showed `metadata: {}` and `client_reference_id: null`, so the webhook matches the order by the `cs_test_…` session id — the simulated event only needs that to match.

**Manual gates replaced with polling:**
- **3C-2 (B1):** polls the order until `cover_pdf.url` and `inner_pdf.url` are both present; fails fast if order `status` = `Error`; asserts `payment_status = Confirmed` once at the end. Defaults 8 × 15s (`b1MaxAttempts`, `b1PollDelayMs`, counter `b1Attempts`).
- **3D-3 (C1):** polls `store_orders.status` until terminal. Terminal statuses are only `Cancelled` (expected for a staging order) and `Error` (fail). Defaults 10 × 20s (`c1MaxAttempts`, `c1PollDelayMs`); counter `pollAttempts` resets automatically when `orderId` changes (`pollOrderId`).
- Both use `setTimeout` in pre-request for the delay and `pm.execution.setNextRequest(pm.info.requestName)` to loop — only works in the Collection Runner / Newman / monitors, not single sends.

**Removed requests for endpoints deleted in the API cleanse:**
- Deleted `3D-1 GET /transaction_webhook_events` (asserted webhook event recorded) and `3D-2 GET /store_order_updates` (asserted HPBC updates logged). Neither set variables. Their intent is now covered by the paid-status check after 3B-2 and the C1 terminal-status poll. Removed the `store_order_updates` wording from 3D-3.

**End-to-end runs (Collection Runner):**
- **Run 1:** failed at `3A-1` with `422 STORY_NOT_READY — Story must be completed before ordering`. Expected: 3A fired straight after story creation, but text + image generation takes ~12–15 min. Confirms the backend guard works.
- **Run 2** (17:15 UTC, after switching 3A to a pre-completed fixture story): 83 passed / 9 failed; ran through to `3B-1`. Failures:
  - `2A-1` "Response error is null" — likely `error` key absent rather than null (assertion issue).
  - `NEG-1B` user/email checks — `/auth/me` nests data under `user`; script assumed top-level fields. Corrected script supplied.
  - `3A-2` "still Payment Pending" — order status after PATCH isn't `Payment Pending`; actual value not yet checked.
  - `3A-3` session id / checkout url not found in a 200 response, and `3A-3b` `checkout_session_id` not written to the order → `checkoutSessionId` likely never set, so the 3B-2 pre-request guard throws (explains "no tests found" in 3B-2).
  - `3A-3c` (negative ownership) returned 500 instead of 404 — request has no `store_orders_id` query param.
  - `3B-1 check_order_paid` not confirmed — runs **before** 3B-2 (the simulated payment), so it can only fail.

Story generation (~12–15 min) won't fit a monitor.

## Decisions made

Decision notes created in `Project/Decisions/` for today's deviations from the planned approach:

- **Payment hop = signed simulated webhook from Postman**, replacing the 2026-10-08 plan of a Stripe CLI one-off plus dev-only simulate flag (CLI fires fixture events unrelated to our checkout session, can't run in a monitor; no simulate endpoint exists). Signed with the test-mode `whsec_`, so real signature validation is exercised. See [[simulate-stripe-payment-with-signed-postman-webhook]].
- **Don't recreate removed endpoints for testing.** Assert outcomes through existing user-facing endpoints; any future ingest/dedup assertions use read-only, admin-gated GETs in a dev-only testing group. See [[avoid-recreating-removed-endpoints-for-testing]].
- **Ordering flow uses a pre-completed fixture story**; story generation gets its own poll-based test (not the monitor). See [[use-fixture-story-for-order-flow-test]].
- **Manual gates replaced with bounded polling** (fail-fast on `Error`, hard fail on timeout). See [[replace-manual-test-gates-with-bounded-polling]].

Not a decision-note item (process choice): not converting the Postman team trial to paid just to restore Agent Mode credits; remaining work done by hand.
