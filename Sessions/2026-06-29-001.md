## Decisions made

- **Profile cap: 1 adult, 6 children per account.** Free within plan — not a paid lever. Commercial levers are generation volume, premium artwork styles, PoD credits.
- **`is_child` immutable and server-set.** Removed from POST inputs entirely; UI is "Add child profile" with no toggle. Cannot be changed via PATCH.
- **Default adult profile permanent for V1.** No deletion, no promotion. Soft-delete guard blocks deleting the default profile, full stop. Multi-adult / promotion deferred post-V1.
- **Child avatar approach: bundled client-side presets.** `avatar_key` (text) stored in DB; frontend resolves to bundled SVG. Rationale: ICO Children's Code data minimisation, eliminates upload moderation surface, on-brand. DiceBear CC BY 4.0 attribution to be added to in-app Licenses screen.
- **Profanity system: two-stage, AI as final arbiter.** Word-list is a signal only (no early exit). AI moderation (`name-moderation-v1`) is the gate. Explicit nuance in prompt: lenient on real names with slur substrings (Hancock, Cassidy), accepts whimsical names and digit-suffix distinguishers.

## Notes / scratchpad

**Key learnings from this session:**
- Word lists are 2010-era moderation. AI moderation with a domain-specific policy prompt handles nuance (Hancock, Cassidy, Scunthorpe, Cumberbatch) that substring matching cannot.
- Postgres `25P02` (transaction poisoning) hides the real error — always dedupe/validate CSV before import.
- Custom Xano function syntax: `function.run "path/name" { input = {...} } as $var` — not `api.function`.
- Don't store image bytes for children's preset avatars: bundled assets + text key is cheaper, faster, more private.
