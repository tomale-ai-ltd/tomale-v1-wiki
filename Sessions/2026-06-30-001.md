## Decisions made

<!-- Filtered to items with architectural/product weight. Cross-checked against constitution, data-model, api-spec, sdd-process-overview, PRD, build-plan, and CTO implementation plan. -->

- **`user_profiles` soft-delete blocks deleting the currently-active profile.** Prevents a broken-token state where the JWT's `active_profile.id` points at a soft-deleted row. Enforced via precondition, fails with 422 `CANNOT_DELETE_ACTIVE`.
- **Schema rename `is_default` → `is_primary`.** "Default" was overloaded; "primary" reads cleaner and extends to future multi-adult support.
- **`user_alerts` scope defined as in-app inbox, distinct from push.** Public surface is READ + mark-read only; creation is internal-only via `create_user_alert()`. Deletion is server-side maintenance.
- **`action_url` (nullable text) chosen over typed entity_type/entity_id FK** for alert deep-linking — simpler, versionable, universal handling on the frontend.
- **API security audit removals:** `instant_story_reviews` (no sharing/audience for V1), `user_activities` (analytics-only, deferrable), `support_requests` (replaced by `mailto:` + ops inbox process, no backend needed).

> These are engineering/product decisions made in the course of executing the documented Phase 1 audit ([[6-api-security-model]]) — none contradict the constitution, data-model, api-spec, PRD, build-plan, or CTO implementation plan. No `Decisions/` note is strictly required by that test, though the three "see decision note" references above are still open (see Blockers).

## Notes / scratchpad

**Learnings captured this session:**
- Xano PATCH endpoints want optional inputs + `first_notempty` coalescing for true partial-update semantics, not required inputs (which force PUT-like behavior).
- Path parameter types must match the table's id type — a `uuid` table with an `int`-typed input silently 404s at the routing layer before endpoint logic runs.
- Renames are cheapest at first divergence — `is_default` → `is_primary` cost one endpoint today vs. six-plus in three months.
- In-app inbox and push notifications are complementary, not either/or (inbox reaches 100% of active users; push only opted-in, ~51% iOS).
- Xano's Swagger export makes Postman collection maintenance ~free via OpenAPI import/merge — same pattern as the frontend's `xano.yaml` sync (~15 min setup, decision note drafted, not yet written).

**Deferred / out-of-scope items captured:**
- Deep-link URL format: custom scheme (`tomalerntest://`) for V1, migrating to Universal Links (`https://tomale.ai/app/*`) pre-launch.
- Push notifications infrastructure (new `user_push_tokens` table) — post-V1 fast-follow, ~2-3 days estimated.
- CC BY 4.0 avatar attribution — in-app Licenses screen, deferred to frontend resumption.
- `/instant_stories/:id/characters` sub-resource — no design blocker, purpose-built replacement for raw join-table exposure.
