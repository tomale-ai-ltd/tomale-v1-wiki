## Decisions made

- Data-model script follows the existing `update-openapi.mjs` pattern (`.env` loading, `die()`, atomic tmp + rename writes), for consistency.
- Metadata API variables are checked only inside the new script, so `update:openapi` stays independent of them.
- Metadata API requests are sequential and retry 429s up to three times (honouring `Retry-After`), then fail without writing.
- `DOMAIN_MAP` is embedded in the script so domain grouping and table-type classification are explicit and reviewed in code.
- `user_profiles` replaces the old expected `user_child_profiles`; `blocked_terms` included as expected live schema drift.
- `audit_store_orders` included as a new live Commerce & Orders table.
- Indexes fetched from `/workspace/{id}/table/{table_id}/index`; unavailable indexes omitted.
- References are not inferred from `_id` field names, because the schema response lacks target-table metadata.
