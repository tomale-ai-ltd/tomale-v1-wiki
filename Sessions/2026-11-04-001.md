## Decisions made

- **Cursor permission model** (Kyle, 04/11, accepted): repo-level committed allowlist of exact command prefixes (never bare `git`/`pnpm`/`npx`/`gh`); a fail-closed hook hard-denies merges, force pushes (`--force`/`-f`, `+` refspecs), pushes to `main`, remote branch deletes, `eas submit`/`eas update`, and forces approval for dependency changes, pushes (including `--force-with-lease`), PR creation, `eas build` and destructive commands; `pnpm install --frozen-lockfile` stays allowlisted; heredoc bodies are ignored. Why: Kyle merges and approves supply-chain changes; Run Mode alone let sandboxed commands through. Recorded in RS-2026-11-04-03.
- **Runtime version policy `fingerprint` instead of `appVersion`** (Kyle, 04/11, accepted). Why: with `appVersion` the SDK 58 builds still matched the old SDK 54 OTA updates at runtime `1.0.0`; `fingerprint` ties updates to the exact native code. Recorded in RS-2026-10-30-07 rather than a separate decision note.
- Kyle asked for the env fix as its own commit (RS-2026-11-04-02) and the fingerprint change inside the rewritten RS-2026-10-30-07 commit.
- **Speckit 007 clarifications** (Kyle): store the access token's issue time on every successful refresh (so the 50-minute foreground check restarts from that refresh); a refresh refused with 400 or 401 signs the user out, while network errors and 5xx keep them signed in (Cursor applied sign-out to every other refresh failure too, including a success without replacement credentials; a missing issue time counts as due for refresh); the crash-report profile id is `auth.active_profile.id` from `GET /auth/me` (ID only, never name or `is_child`; omitted when absent; profile switching out of scope).
