## Decisions made

D1 — **Per-child story visibility model**: A story is visible only to its creator profile and any parent profile on the same account. No cross-profile or cross-account sharing in V1. Single FK `user_profiles_id` on `instant_stories`, set server-side at creation. No join table in V1. Read enforcement lives in the endpoint, not the frontend. → [[per-child-story-visibility]]

D2 — **Fail-closed active profile resolution**: When `active_profile` cannot be resolved from extras, the endpoint fails closed with a re-login error. No fallback that elevates a missing-extras token to the default or parent profile. Reinforces the no-silent-privilege-escalation principle from [[6-api-security-model]].

D3 — **List and detail projection split**: GET all returns a lightweight card projection; GET single returns a curated detailed projection. The field difference is a UX and performance choice, not a security boundary. Anything that must never reach a client is excluded from both.

D4 — **Legacy story ownership on backfill**: Legacy stories with a null creator are assigned to their account's default adult profile. The adult default has `is_child == false` so it sees all account stories; child profiles never inherit legacy content. Covered within [[per-child-story-visibility]].

D5 — **Parental gate on profile switching** (proposed, not yet built): Switching into a parent profile from a child profile must require an account-level PIN, verified server-side in select_profile. → [[parental-gate-on-profile-switch]]

> Note: D1 deviates from [[2-build-plan]] (no join table in V1 is a scope reduction from planned sharing model). A manual decision note at Project/Decisions/ for per-child-story-visibility is called out.
