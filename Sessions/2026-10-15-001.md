## Summary

Found why order 134 never reached HPBC (blank `hpbc_order_id` stored as `""`, not null) and the root cause of the `created_at` overwrite: Xano's hidden-fields behaviour writes any function input/variable named like a column into that column. The same behaviour was overwriting the buyer's gift message on every HPBC callback. The `hpbc_update_order` status guard was found never to have been published and was republished. `_tests` order folders passed 55/55 on orders 169 and 170; Folder 4 (cancel and refund) was built but stopped at 4A.

## What I actually did

**Order 134 / HPBC submission**
- `hpbc_submit_due_orders` task and `reconcile_order_fulfilment` tested `hpbc_order_id == null`; the text field is stored as `""`, so the order never matched.
- Task query now `(hpbc_order_id == null || == "")` and `hpbc_lock != true`; precondition uses `hpbc_order_id|is_empty`, non-empty `cover_pdf.url` / `inner_pdf.url`, and `status != "Error"`.
- Order 134 then submitted and reached In Production.

**`created_at` overwrite: root cause**
- Audit rows showed the cover PDF edit setting `created_at` to the executor run timestamp.
- `papermill_generate_pdf_cover` / `_inner` had an input named `created_at`; renamed to `run_created_at`, and `pdf_worker_tick` passes `$now` under that name.

**`message` overwrite**
- `hpbc_update_order` had an input named `message`, overwriting `store_orders.message` (buyer's gift message) with Pureprint text on each callback. Renamed to `update_message`; both HPBC status callback endpoints map `message` to `update_message`.

**`hpbc_update_order` guard**
- Published function had the new header comment but old code. Republished from `hpbc_update_order_2026-10-14.xs` (forward-only status rules; fails closed on empty `hpbc_order_id` or `status`). Previously an empty id could match any unsubmitted order.

**Other**
- `hpbc_create_order` 14b confirmed already live.
- `payment_status = Refunded` writes added in `stripe_refund_order` (test and real branches) and the Stripe webhook refund branch (succeeded; revert to `Confirmed` on first failure). Webhook attempt counter uses `first_notnull:0`.
- `order-fulfilment-flow.md` replaced from draft (backup `.bak-20261015-130015`).

**Postman `_tests`**
- 3D-3 skip guard added; orders 169 and 170 passed 55/55.
- Audit rows on 169 confirmed `created_at` stable, `message` kept, and an Error callback after Shipped changed nothing.
- Folder 4 (4A–4G plus check requests) built; run stopped at 4A due to a missing base variable in its URL.
