## Decisions made

- **Phase 1 is signed off** (2026-10-23), with 86/86 `_tests` as the evidence. `6-api-security-model`'s close-out section is the authoritative Phase 1 record until the matrix is rebuilt from the OpenAPI export.
- **Checkout has an order-status guard:** `stripe/create_checkout_session` refuses (400 `ORDER_NOT_PAYABLE`) unless the order is `Draft` or `Payment Pending`.
- **Parental-approval order gate on both order create and checkout** (400 `STORY_AWAITING_APPROVAL`); null-safe so legacy rows can't bypass it.
- **Request history stays on for token-issuing auth endpoints while only test accounts exist.** Accepted risk: tokens appear in history outputs; protected by being the only workspace user, 2FA, and the docs/metadata tokens kept in a gitignored `.env`. Turn history off on `auth/login`, `auth/refresh`, `auth/complete_magic_link` (and `auth/signup` if it issues tokens) **before launch**, relying on `user logs` for auth visibility. Revisit if anyone else gets workspace access.
- **The `app` group spec is the API contract for Cursor**; `XANO_APISPEC_URL` points at the group (`apispec:1pgd39RE`), not the workspace. `npm run update:openapi` stays as the generator.
- **Knowledge architecture (agreed in principle; to be written up in `Project/Plan/knowledge-architecture.md` and approved before any change):**
  1. *Ownership:* the Cursor repo owns the engineering specs (constitution, data model, OpenAPI contract, speckit feature specs); the vault owns product, PRDs, decisions, architecture explanations and history. The vault's `Project/Cursor` copies are retired. Decisions made outside Cursor that affect repo specs are queued in `Current/repo-sync.md` and applied by Cursor ("apply open items"). Claude never edits the repo.
  2. *Tiers:* a vault `Current/` folder for living docs (`CURRENT.md`, architecture flows, security model, `_tests` doc, PRD index); repo specs symlinked into the vault as read-only `Repo/`; Cursor adds `Current/` as a second workspace folder; superseded baseline docs move to `Project/_archive`.
  3. *Frontmatter:* `type` (fixed list), `status` (docs: draft/current/historical; decisions: proposed/accepted/superseded), `version` and `last_verified` for living docs, `supersedes`/`superseded_by` and `related` as quoted wikilinks, `owner` (repo/vault) for specs. Applied by script, then reviewed; broken links fixed in the same pass.
  4. *Generated specs:* the OpenAPI contract comes from `npm run update:openapi`; a new `update:datamodel` script (Metadata API, read-only token) generates `data-model.md`. Neither is hand-written again.
  5. *Automation:* the decision-note task gains catch-up processing (everything since the last successful run, not just "today") and a reconcile step that *proposes* living-doc edits in `Current/pending-updates.md`; a weekly staleness check is added. Automations don't edit living docs directly.
  6. *Retire the Obsidian LLM-wiki plugin* and delete `wiki/` once git is in place (it's generated output and stays in git history). Claude and Cursor are the query layer.
  7. *Agent access:* Claude Project knowledge reduced to Tier 1 docs; Claude reads the full vault through the folder link; Cursor works from the repo plus `Current/`. Don't touch `specify-rules.mdc` (speckit regenerates it); add separate `tomale-project.mdc` (always) and `tomale-api.mdc` (`api/**`) rules; fix the AsyncStorage token note at its source in the 002 plan.
  8. *Git for the vault:* a private GitHub repo `tomale-v1-wiki`, the Obsidian Git plugin (auto commit/pull), commit straight to `main` day to day, a branch plus PR review for each restructure stage. Never nest the vault and the Cursor repo.
  9. *Process:* plan doc and decision notes first → approval → vault backup and git → staged changes, each checked.
- **Postman suite in CI: not now.** It creates Stripe sessions, Papermill PDFs and HPBC staging orders. Later: split into a fast, safe subset (auth, NEG, ownership) and the full order flow, run with Newman in a GitHub Action (manual trigger and pre-release).
