## Decisions made

Candidates for decision notes in `Project/Decisions/`:

- **Staging HPBC terminal status is Order Confirmed.** C1 passes on Order Confirmed (Cancelled also accepted); based on Pureprint's confirmation that staging orders are never auto-cancelled.
- **Delete, don't recover, stuck pre-production stories** via a manually-run, endpoint-less admin function with dry run by default; characters and orders never deleted.
- **`hpbc_create_order` is a single fail-closed request**; SKU defaults to staging; never resubmits an order that already has `hpbc_order_id`.
- **We don't send preflight, production timescales, `unitPrice` or `unitCost` to HPBC**; these are configured on Pureprint's side.
- **Tracking stored on `store_orders`** (`tracking_url`, `tracking_number`) from the Shipped callback; later callbacks never clear it.
- **Simulated HPBC callbacks (3D-2, 3D-3) run after C1** and assert via a follow-up GET; skipped when `hpbcOrderId` is missing so one cascade failure doesn't cascade into many.
- **`hpbc_order_id` check stays immediately after the PDF poll** (it proves our submission, separate from Pureprint's Order Confirmed).
- **Order runs exclude the story folder**; story generation tested separately (consistent with [[use-fixture-story-for-order-flow-test]]).
- **Postman monitor deferred to launch.** Pre-launch, run the collection manually after backend changes and before go-live orders. At launch, daily monitor with run kept under the 10-minute Free-plan limit (B1 ~24 attempts, C1 ~6).
