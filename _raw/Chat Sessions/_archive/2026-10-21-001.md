## Decisions made

- **`/admin/upload/image` is disabled until something uses it.** Re-enable it, with type and size validation, when image-to-image work starts.
- **Rate limiting:** Xano's paid plans don't rate-limit at platform level. The free plan's 10 requests per 20 seconds is the only platform limit. So limits have to be added per endpoint with Xano's Rate Limit function. Phase: to confirm, with Phase 2 before launch recommended. Priority targets:
  - auth (login, OTP, password reset)
  - order create and cancel
  - story and image generation, because of OpenAI cost
- **Fixed before Phase 1 sign-off:**
  - `auth/refresh`: return 401, not 200, on an invalid or expired refresh token (done 21 Oct)
  - money units drift: `subtotal` and `shipping_amount` to integer pence
  - ordering: a story awaiting parental approval can't be ordered
- **`/model` endpoint:** deleted.
- **Postman:** delete the old `app` folder auto-login script.
- **Test switches** such as `simulate_*` are optional inputs, never required.
- **Client auth session handling.** `auth/refresh` returns 401 with `payload = "invalid_refresh_token"` when a refresh token is invalid or expired. Rules for the app:
  - One Axios response interceptor handles every 401, in line with the constitution's "Axios interceptors" standard.
  - On a 401 it runs a single refresh (concurrent 401s share it) and retries the original request once. It never refreshes when the 401 came from `/auth/*`.
  - On `invalid_refresh_token`, it clears the tokens and resets the Zustand auth store. The Expo Router root layout then redirects to login.
  - Network errors don't log the user out.
  - The app refreshes proactively shortly before the 1-hour expiry when it returns to the foreground.
  - Tokens move from AsyncStorage to `expo-secure-store`. This settles the "future hardening decision" in `9. AsyncStorage.md`.
- **Executor runs log only small status fields,** never full API payloads.
