`### Xano API group consolidation (major unplanned scope)`

``**Problem uncovered:** Each Xano API group has a unique base URL slug. The original structure had 7 separate groups: `auth`, `commerce`, `content`, `integrations`, `system`, `users`, `utilities`. The frontend can only point at one base URL via `EXPO_PUBLIC_API_BASE_URL` — so only one group's endpoints would have worked.``

`**Decision:** Consolidate to two groups.`

`| Group | Purpose | Contents |`

`|---|---|---|`

``| `app` | Everything the React Native app calls | All endpoints from auth, commerce, content, system, users, utilities |``

``| `webhooks` | External callbacks only | Stripe webhooks, HPBC webhooks (sendgrid receivers if applicable) |``

`**Rationale:**`

``- The generated OpenAPI client assumes one `servers:` URL — multiple base URLs would fight the generator``

`- The 7-group structure was developer-facing organization, not architectural — Xano supports nested folders within a group for visual organization without affecting URLs`

``- Matches production API conventions (e.g. `api.stripe.com/v1/*` rather than `auth.stripe.com` + `charges.stripe.com`)``

`- Mirrors the API security model classification (app endpoints vs webhook endpoints)`

`- Future-proof: when dev/prod Xano are split, each environment has one URL per group`

``**Endpoints reclassified out of `integrations`:**``

``- `stripe/create_checkout_session` → `app` (called by the app, not by Stripe)``

`` - `stripe/webhook_*` → `webhooks` ``

`` - `hpbc/webhook_*` → `webhooks` ``

``- `sendgrid/*` and `stability/generate_image` flagged for review — likely internal Xano functions, not API endpoints``

`` **New `app` group base URL:** `https://api.tomale.ai/api:1pgd39RE` ``

`Created the missing piece in the magic link flow. The deeplink callback screen was incomplete — it assumed the URL contained a usable bearer token, but the email link actually contains a single-use magic-link token that needs to be exchanged for a bearer.`

``- Accepts `token` (the magic link token from the email URL)``

`` - JWE decodes the token using `$env.magic_jwt_secret` ``

`- Validates: user exists, magic_link.token matches, magic_link.used == false, magic_link.expiration >= now`

`- Issues fresh refresh token + auth token (preserving the active_profile extras pattern established in previous sessions)`

`- Creates new user_sessions record`

`- Marks magic_link as used to enforce single-use`

`## Decisions made`

`### Magic link URL strategy: web intermediary, not direct custom scheme`

``**Decision:** Magic link emails contain a standard `https://` URL to the Squarespace site, which then prompts the user to open the app. Not a custom `tomale://` scheme.``

`**Rationale:**`

`- Flexible enough to handle web and mobile from the same email`

`- Custom schemes are fragile (some email clients block them, no graceful fallback if app not installed)`

`- The web-intermediary pattern is what universal links + smart banners are designed for`

`- Handles future desktop users + users without the app installed (App Store redirect fallback)`

`**Trade-off:** Current UX has an extra "Continue to open app?" tap in the browser. Acceptable for V1. Pre-launch improvement deferred (see deferred items).`

`---`

``### Two-group Xano API structure (`app` + `webhooks`)``

`See "Xano API group consolidation" above. Decision rationale and endpoint reclassification documented there.`

`---`

`### Strict env validation, no fallbacks`

`**Decision:** Env vars throw at startup if missing, in all environments (dev included). No hardcoded fallback URLs anywhere.`

`**Rationale:** Fallbacks hide misconfiguration — exactly the bug class we want to surface loudly. Strict validation is cheap, the failure mode is clear, and it prevents the silent-fallback-to-stale-URL bug we just fixed.`

`---`

``### EAS env config lives in `eas.json`, not the EAS dashboard``

``**Decision:** Non-secret `EXPO_PUBLIC_*` values are version-controlled in `eas.json` per-profile `env` blocks. EAS dashboard reserved for true secrets (Sentry auth token, future API keys).``

`**Rationale:** Config in the repo is reviewable in PRs and reproducible across machines. Matches the "least hacky" principle of keeping non-secret config visible.`

`---`

`### Per-profile env values now, even though dev/preview/prod point at the same Xano`

``**Decision:** Set up `development`, `preview`, `production` env blocks in `eas.json` now, all currently pointing at `https://api.tomale.ai/api:1pgd39RE`. When Xano is split into separate dev/prod instances, just change the value per profile — no code or config restructure needed.``

`**Rationale:** Forward-compatible at zero cost.`

`---`

`### Magic link auth completion via dedicated endpoint, not URL-embedded bearer token`

``**Decision:** Email contains a single-use magic-link token (JWE-encoded, references a token stored on the user record). The callback screen exchanges this for a bearer token via `POST /auth/complete_magic_link`. The bearer token is never sent in URL parameters.``

`**Rationale:** Bearer tokens in URLs end up in email server logs, mail client history, browser history, and clipboard. The single-use token with separate validation is the correct security pattern.`

`## Notes / scratchpad`

``- **Xano gotcha**: API group base URL changes when endpoints are moved between groups. The path within the group stays the same (`/auth/login` stays `/auth/login`), but the prefix changes. Always verify base URL after restructure.``

`- **Xano gotcha**: Deleting an API group deletes all endpoints inside it. Audit logs offer a "Restore API Group" action, but workspace-level backup restore is cleaner for structural changes.`

``- **Xano gotcha**: The `|set` filter on a JSON/object field — verified preserves the rest of the object's fields, doesn't replace. So `data = { magic_link: $user.magic_link|set:"used":true }` correctly preserves `token` and `expiration`.``

``- **Expo / EAS best practice**: `EXPO_PUBLIC_*` values are baked into the JS bundle at build time. Not secrets. Real secrets belong on the server or in EAS secrets for build tooling only.``

``- **Expo / EAS best practice**: One env module (`config/env.ts`) reads `process.env.EXPO_PUBLIC_*` and exports a typed object. Rest of the app imports from there. Easier refactors, easier testing, single point of validation.``

``- **OpenAPI codegen**: The `servers:` block in the generated yaml is a fallback default. Runtime base URL is read from env, not from the generated client. So the spec's `servers:` URL can be wrong without breaking the runtime app.``

``- **Magic link contract**: email link → single-use token → `POST /auth/complete_magic_link` → bearer token + refresh token → `/auth/me` → authenticated route. Never put the bearer token in the URL.``
