## Summary

**Current milestone:** Phase 1 close-out (Security & Data Integrity + flow tests), per [[5-cto-implementation-plan]] and [[2-build-plan]].
**Feature/area of focus:** Order 134 not being sent to HPBC; the `store_orders.created_at` overwrite; the `message` overwrite; refund status writes; cancel and refund Postman tests.
**Carries over from:** [[2026-10-14-001]]

Found why order 134 never reached HPBC, and the root cause of the `created_at` overwrite. The overwrite comes from Xano's "hidden fields" behaviour: when a function has an input or variable named the same as a table column, Xano writes its value into that column on add and edit steps, even if the step doesn't list the column. The same behaviour was overwriting the buyer's gift message (`store_orders.message`) with Pureprint's status text on every HPBC callback. Also found that the `hpbc_update_order` status guard had never actually been published. The `_tests` order folders passed 55/55 twice (orders 169 and 170). Folder 4, the new cancel and refund tests, was built.

## What I actually did

**Order 134 not sent to HPBC**
- The `hpbc_submit_due_orders` task and `reconcile_order_fulfilment` checked `hpbc_order_id == null`. The field is text and is stored as `""` when blank, so the order never matched.
- Fix:
  - Task query: `(hpbc_order_id == null || == "")`, and `hpbc_lock != true`.
  - Precondition: `hpbc_order_id|is_empty`, a `cover_pdf.url` / `inner_pdf.url` not-empty check, and `status != "Error"`.
- Order 134 then went to HPBC and reached In Production.

**`created_at` overwrite: root cause found**
- The audit rows showed the cover PDF edit changing `created_at` to the executor run's timestamp.
- Cause: Xano's hidden-fields behaviour (documented at docs.xano.com/hidden-fields-fix). An input or variable whose name matches a column is written into that column by add and edit steps that have `enforce_hidden_fields = false`.
- `papermill_generate_pdf_cover` and `papermill_generate_pdf_inner` had an input called `created_at`. Both were renamed to `run_created_at`, and `pdf_worker_tick` now passes `$now` under that name.
- The inner PDF function didn't visibly change `created_at` because both jobs were claimed in the same tick with the same `$now`.

**`message` overwrite**
- `store_orders.message` holds the buyer's gift message to the book's recipient. Every HPBC callback was overwriting it with Pureprint's text, because `hpbc_update_order` had an input called `message`.
- Renamed the input to `update_message`. Both HPBC status callback endpoints now map `message` to `update_message`.

**`hpbc_update_order` status guard was never live**
- The published function carried the new header comment but still had the old code underneath.
- Republished from `hpbc_update_order_2026-10-14.xs`. That adds the forward-only status rules and fails closed when `hpbc_order_id` or `status` is empty.
- Before this, a callback with an empty id could have matched any unsubmitted order.

**Other changes**

## Blockers / questions

- The image pipeline functions have the same `created_at` input pattern (fixed on 21 Oct).
- Executor run lookup by timestamp is fragile, and the run row is created after the function starts (fixed on 21 Oct).
- The HPBC callback bearer token was shared in chat. The risk is low; rotate it at some point.
- Xano AI sweep for inputs or variables named like columns was requested; the results are pending.

---

## Decisions made

- **Don't name a function input or variable after a column the function writes to.** Xano's hidden-fields behaviour writes it into that column. Fix by renaming, not by switching `enforce_hidden_fields` on: with it on, unlisted fields may be reset to their table default.
- **`store_orders.message` is the buyer's gift message only.** Callback text goes to `store order updates`.
- **Executor runs are found by `id`, not by timestamp** (scoped as task 10 and done on 21 Oct).
