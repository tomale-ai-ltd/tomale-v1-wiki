## Decisions made

- **Moderate free-text user instructions with the existing `moderation-text` policy through a general function** (Kyle, 05/11, accepted). New `ai pipeline/content_moderation_text` (inputs `payload`, `users_id`, `entity`, `entity_id`) loads the default active `moderation-text` data model and returns the raw result; callers decide. Policies stay in `data models` rather than in function code. Why: `moderation-name` is a names-only policy (it blocked "wearing a red scarf"); a separate instruction policy would duplicate and drift from the Tomale content policy. For character images, anything but `enforcement: none` is refused (parental oversight cannot gate a household-wide image); `flag_account` writes `moderation_flags`. Rejected: a hard-coded instruction policy in a new function.
- "Draw again" uses the same image model as generation (data model setting), not `dall-e-2`.
- Child refusals use 400 `PARENT_PROFILE_REQUIRED` per the constitution; `DELETE /users/user_profiles/{id}` still uses 403 `PROFILE_NOT_PARENT` (align later).
