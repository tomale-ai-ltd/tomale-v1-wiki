# Session Note — 2026-06-29-001

Resumed Phase 1 user_profiles work. Completed POST /user_profiles end-to-end including a two-stage name validation system (word-list + AI moderation) and locked the avatar design approach. Schema changes pending for PATCH.

## Decisions

### Profile cap
- **1 adult, 6 children per account.** Free within plan, not a paid lever.
- Rationale: matches Netflix/Disney+ category norm; gating profiles behind payment punishes large families. Commercial levers live in generation volume, premium artwork styles, and PoD credits — not profile count.

### is_child immutability
- Locked at creation. Cannot be changed via PATCH.
- `is_child` removed entirely from POST inputs. Server-set to `true`. UI is "Add child profile" — no toggle, no ambiguity.

### Default profile
- Adult default profile is permanent for V1. No deletion, no promotion via soft-delete.
- Consequence: soft-delete guard becomes "block deleting the default," full stop.
- Multi-adult and adult-promotion deferred post-V1.

### Avatar approach
- **Child profile avatars are bundled client-side preset assets**, not uploads.
- Rationale: ICO Children's Code data minimisation; eliminates a moderation/abuse surface; matches kids' platform category norm; on-brand for storytelling app.
- Adult profiles continue using `/users/me/image` for real photos. No change there.
- Schema: `user_profiles.avatar` (image) to be removed; replaced with `avatar_key` (text, nullable).
- Avatar art sourced from DiceBear (CC BY 4.0). ~19 SVGs generated in Adventurer-style, saved to `tomale-rn-v1/assets/avatars/`.
- Frontend resolves `avatar_key` to a bundled SVG. Database stores key only. UI never shows the key string.

### Profanity / content moderation system

Two-stage name validation, both stages always run.

**Stage 1 — word-list signal**
- `blocked_terms` table created with 404 unique entries sourced from `dsojevic/profanity-list` (severity ≥ 2).
- Substring matching against both `clean_input` (lowercased, trimmed) and `compact_input` (whitespace stripped).
- Asterisk-stripping applied to patterns at runtime (source uses `*` as obfuscation markers).
- Now used as informational signal only — does NOT block on its own. Hancock false-positive case resolved by removing the early-exit.
- Kept available for future telemetry (training data, rate-limiting signal).

**Stage 2 — AI moderation (final arbiter)**
- New function `ai_pipeline/content_moderation_name` modelled on the existing story moderation function. Stripped of all instant_story-specific logic.
- New data_models row: `type = "moderation-name"`, version 1.0, slug `name-moderation-v1`.
- Name-specific prompt drafted, derived from Tomale Content Moderation Policy V1.0 but scoped to name evaluation. Explicit nuances added: lenient on real names containing slur substrings (Hancock, Cassidy, Scunthorpe, Cumberbatch), accepting of whimsical character names, treats digit-suffixed names (David3, Sarah2) as legitimate distinguishers.
- Output schema simplified: pass/blocked only. No parental_oversight, no flag_account branches.
- Token usage logged: `entity: "user_input"`, `entity_id: $auth.id`, `type: "content_moderation"`.
- Fail-closed on OpenAI errors (3 retries, 15s timeout, 2s sleep between).

**Orchestrator function**
- `admin/check_for_profanity` rebuilt as a two-stage orchestrator: word-list signal + AI moderation. Returns `{ pass, reason, blocked_reason }`.
- Caller signature now requires `users_id` in addition to `text`.

## Issues encountered & resolved

- **Postgres `25P02` on CSV import** — initial CSV used JSON array syntax for `tags` field; Xano CSV importer doesn't reliably handle `text[]` columns. Dropped tags column entirely, re-imported with 3 columns (`slug`, `match`, `severity`). Subsequent failure was caused by 2 duplicate slugs in source data — resolved by deduping at the Python-script stage with merged match patterns and max severity.

- **Lambda map syntax** — Xano expects `lambda_map:"$this.match":10` (with quoted lambda string and required timeout argument), not the `map:($this.match)` parenthesised form. Visual builder generates the canonical form; verified via "switch to XanoScript" toggle.

- **Hancock false positive** — substring matching against asterisk-stripped patterns (`cock` → matches Hancock). Resolved architecturally by demoting stage 1 to a signal and letting stage 2 (AI) be the final arbiter, since the prompt explicitly handles this case.

- **David3 false positive** — AI moderation flagging digit-suffixed names as suspected leetspeak. Resolved by adding an explicit nuance line to the prompt covering common digit-suffix distinguishers.

- **OpenAI call from Xano** — custom function invocation syntax is `function.run "path/name" { input = {...} } as $var`, not `api.function`.

## Learnings / principles reinforced

- **Word lists are 2010-era moderation.** Static lists can't distinguish "Hancock" from "cock". AI moderation with a well-written, domain-specific policy prompt outperforms list-based filtering for any case requiring nuance. Use word lists as signals (telemetry, rate-limiting), not as gates.
- **Substring matching is a one-way trade-off.** Catches evasion (`uracunt`, `fckface`) at the cost of legitimate names (`Hancock`, `Cassidy`). Acceptable when AI moderation is downstream to rescue legitimate names.
- **Postgres transaction poisoning (`25P02`) hides the real error.** First failed INSERT aborts the transaction; subsequent inserts all return 25P02 with no detail. Always dedupe and validate CSV data before import; never trust silent unique-constraint failures.
- **Don't store image bytes for children's preset avatars.** Bundled assets + text key is cheaper, faster, more private, and removes a whole class of moderation/abuse surface.
- **Custom function calls in Xano use `function.run`**, not `api.function`. Visual builder + XanoScript toggle is the fastest way to discover canonical syntax for unfamiliar XanoScript constructs.
