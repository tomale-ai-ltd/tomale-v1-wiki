- `create_checkout_session` now returns only `checkout_session_id`, `url` and `amount_total`. The LIVE branch had the same shape and would have returned the live secret key to customers.
- Rolling the Stripe test secret key was recommended; it appeared in the API response, in Postman run history and in chat. Not confirmed as done.
- New 3A-3 tests: CS2 asserts a `cs_test_` session ID, CS3 a `checkout.stripe.com` URL, and CS5 "no secrets in response" (no `sk_`, no `Authorization`). Variables are now set outside `pm.test` so a failed assertion can't skip them.

## Decisions made

Candidates for decision notes in `Project/Decisions/`:

- **Xano is the single source of truth for physical book prices; Stripe totals are verified server-side before a checkout URL is returned.**
  - Immediate fix: correct the price IDs, and add the amount + currency + status guard in `create_checkout_session`.
  - Agreed target (deferred until the flow test passes): build Stripe `price_data` from Xano `amount` and drop book Stripe price IDs.
  - Subscriptions still need per-platform price IDs (Stripe recurring, Apple, Google). Xano records the IDs and expected amounts, with a planned daily Stripe price reconciliation.
  - Physical goods can't use Apple/Google in-app purchase, so books remain Stripe-only.
- **V1 sells in the UK in GBP only; multi-currency is deferred.**
  - Done now: currency populated, amounts in pence, guard checks currency.
  - Deferred design: a `product_prices` table (product × currency × market); shipping by destination zone; Stripe Tax; Apple/Google handle local subscription pricing.
  - Check international shipping, duties and VAT with Pureprint and an accountant before adding a market.
- **Story status lifecycle formalised:** Draft → Preparing (moderation passed, text generating) → In Queue (images queued) → Done, with Blocked from moderation. `story_completion_check` keys off In Queue. This prevents early completion and makes regeneration on a Done story a no-op.
- **`/model` removed from the flow test;** the endpoint's fate is pending the chatbot preview question.
- **Stuck-story check instead of a long Done poll.** Each run asserts that no story has sat in Preparing or In Queue for more than 45 minutes. This keeps runs monitor-sized and catches completion regressions within one run.
- **Accepted risk:** page text writes pages by AI-returned IDs. Given strict structured outputs and 600+ generations without incident, no ownership check on page IDs for now.
- **Moderation fail-open re-rated to normal priority** because child visibility is enforced by allow-list on both story endpoints. Hardening (fail-closed `else`, allow-list gate) is still planned.
