`### Postman story-generation flow-test harness`

`Built a repeatable harness rather than relying on manual runs.`

``- New dedicated collection, `Tomale — Flow Tests`, separate from the OpenAPI-imported collection. Reason: the imported collection is regenerated from the OpenAPI spec (itself on the close-out list to refresh), and a reimport would clobber hand-built tests. A separate collection is insulated from that churn and fits the existing three-collection model (app, webhooks, metadata).``

``- Two folders: `auth` (login, auth.me) and `story generation` (the five POSTs), ordered in execution sequence.``

``- Collection-level Bearer auth using `{{bearerToken}}` from the environment, inherited by all requests.``

`- Chained ids captured as collection variables (run-scoped, correct for transient values):`

``- `POST /instant_stories` → `storyId` from `instant_story.id` (nested object).``

``- `POST /characters` → `characterId` from `id` (flat, top-level).``

``- Both captures use a fail-fast assertion (`pm.expect(id).to.be.a("number")`) so a missing id stops the run loudly rather than silently chaining `undefined`.``

``- Hardcoded ids (516, 611) swapped for `{{characterId}}` / `{{storyId}}` across path params and bodies on the model and page_text requests.``

``- `characters` body `instant_stories_id` set to `{{storyId}}` to reproduce the chatbot's create-story-with-characters flow and exercise the `instant_story_characters` mapping. The endpoint does not require it (a character can be created outside the flow and mapped later), so this is faithful to the model, not a new coupling.``

``- Pre-request clears stale `storyId` / `characterId` so a failed run cannot leave ids that make the next run look like a pass.``

``- Captures live in Scripts → Post-response, appended after the existing Postbot tests. (Postman has renamed the tabs: Tests → Scripts → Post-response, Pre-request Script → Scripts → Pre-request. Same `pm.*` API.)``

`### Async completion handling`

Chose Option A (manual gate): run the five POSTs (green in seconds — sync steps done plus jobs queued), wait ~15 minutes, then one GET asserting the story is done with all page images present. The character image (~30 seconds, single image) finishes long before the story completes, so it needs no separate assertion; the story wait covers it.``

`### Order fulfilment test — design started`

`Began the next point: proving and making testable the order → checkout → payment → PDF → HPBC chain.`

``Reframed the remaining work. The individual hops are already proven from the July sessions: the Stripe `webhook_payment_confirmation` across all five branches (happy, duplicate, bad-signature 401, unknown-event stored and acked, missing-order failed), and both HPBC callback endpoints across all four cases each. So what remains is:``

``1. The A1 `create_checkout_session` assertion (never finished).``

`2. The joined end to end proof that the hops connect — the deferred full payment→HPBC test, now unblocked since the parts are stable.`

``The chain as it runs live: create store_order → `GET /stripe/create_checkout_session` (order → Payment Pending) → payment → `POST /stripe/webhook_payment_confirmation` (updates order, writes store_order_update and transaction, triggers PDF orchestrator) → `pdf_jobs` / executor populate `cover_pdf` and `inner_pdf` → DB trigger calls `hpbc_create_order` (sets `hpbc_order_id`) → HPBC callback `POST /hpbc/webhook_statusCallbackUrl` updates status.``

`Identified the key design fork: Postman cannot complete a hosted Stripe checkout or forge Stripe's signature, so the payment hop cannot be driven in a pure Postman run the way story-gen chains. Three options on the table:`

``- **Stripe CLI** (`stripe trigger` / `stripe listen --forward-to`) — fires real signed test events at the webhook. Cleanest and truest, but a terminal tool alongside Postman, not one runner.``

``- **Dev-only simulate flag** on the webhook — mirrors the executor `simulate_*` pattern, keeps the whole chain in Postman, but tests a slightly different code path than prod.``

`- **Manual browser checkout** with a test card (4242…) — Stripe fires the real webhook, Postman picks up from PDF readiness. Truest end to end, one manual click.`

`Working lean: Stripe CLI for a real one-off proof, plus a simulate flag for the repeatable harness.`
