## Blockers / questions

- **Sign-out is client-only: there is no Xano logout endpoint.** After a user signs out in the app, their refresh token (and the `user_sessions` row) stays valid on the server until it expires, so a copied token could still be refreshed. Needs a backend `auth/logout` (revoke the session / refresh token) before launch; out of scope for speckit 007. Added to [[pre-launch-checklist]] §1.

- **Speckit 007 clarify and plan done** (uncommitted on `007-foundations-session`). Clarify: crash-report profile id = `auth.active_profile.id` from `GET /auth/me` (ID only, never name or `is_child`; omitted when absent), issue time stored on every refresh, refresh 400/401 signs out. Plan: Zustand persisted via `expo-secure-store` (`AFTER_FIRST_UNLOCK`, chunked) and memory on web; Axios single-flight refresh; type guard for `active_profile` since the generated `/auth/me` type doesn't describe `auth`. `@swc/helpers` 0.5.24 published 04/11, so RS-2026-11-04-01 waits until 11/11. Claude's plan review: treat 429 and timeouts like network/5xx (stay signed in), carried into `/speckit.tasks`.
- **For M3 backend prep:** `auth/login` and `auth/signup` don't return `session_id` (only `complete_magic_link` does), but `select_profile` requires it. Password-login sessions will need `session_id` from the backend (login/signup response or `/auth/me`) before profile switching.

Why: with `appVersion` the SDK 58 builds still matched the old SDK 54 OTA updates at runtime `1.0.0`; `fingerprint` ties updates to the exact native code.
