## Goal

Families can see, make and look after their characters. Parents and children browse a picture-led carousel; parents also get a searchable grid, archive and delete. A new character is made with a simple form and drawn in the background. Any character can be favourited or drawn again with a short instruction.

## Screen flow

- `app/(main)/(tabs)/characters/index.tsx`: 104 carousel (opens first) ⇄ 101 grid (parent only), empty state
- `app/(main)/characters/[id].tsx`: 102 detail
- `app/(main)/characters/create.tsx`: 103 form (replaces `app/(main)/create-character.tsx`)
- Sheets: 105 quick actions, delete confirmation, draw again; Create tab quick menu
- Mock-up reference: the "Tomale Characters screens" canvas (artboards named 101–105, child view, empty state, Create tab)

**Navigation rules:**

- Characters tab opens the carousel. Parent: a header toggle switches to the grid; the last view is remembered on the device. Child: carousel only.
- Swipe sideways between characters; tap the card to reveal its panel (parent: description, Make a story, Draw again, More, Stories with [name]; child: Make a story, Favourite, Draw again, their stories).
- "+" (parent header) and the empty state's button → 103 form. Create tab → quick menu: Make a character → 103; Make a story → "coming soon" until 009.
- Save on 103 → back to Characters with the new character first, showing "Drawing [name]…" until its picture arrives.
- "Make a story" buttons ship disabled with "Coming soon" (story creation is 009).

## Scope (this slice only)

- Carousel (parallax cards with Reanimated: neighbours peeking, picture shifts inside the card, tap to reveal); grid with search by name, Favourites filter and, for parents, Archived.
- Cards: picture (or the "Drawing [name]…" placeholder when `cover_image` is null), name, favourite star, "In N stories" from `stories_count`.
- Detail: picture, name, favourite toggle, description, "In N stories", "Made [date]" from `created_at`, Draw again, More (parent), Stories with [name] (`GET /instant_stories?characters_id=`).
- Favourite / unfavourite (anyone); archive / unarchive and delete with confirmation (parent only, hidden for children).
- Create form: name and description; server refusals shown on the right field (`NAME_NOT_ALLOWED` on name, `CONTENT_REJECTED` on description).
- Draw again sheet: optional instruction (max 200), refusals `CONTENT_REJECTED` and `IMAGE_JOB_IN_PROGRESS` shown inline; the old picture stays until the new one is ready.
- Picture state from `picture_status`: `drawing` shows "Drawing [name]…" and refreshes that character (`GET /characters/{id}`) every 15 s while the screen is open, up to 10 minutes, then "Still drawing, check back soon"; `failed` shows "We couldn't draw [name]. Try again" (opens Draw again); `ready` shows the picture.
- Empty state; Create tab quick menu; child Characters view.
- Zustand `characters` store with the list cached for instant display; refetch on focus.
- Copy follows the design-system README (sentence case, warm, no jargon). All text from the mock-ups.

## Out of scope

- AI character chat (Slice 500 / 012); story creation and linking from a story (009); picture allowances and "limit reached" (M8); Home dashboard (later slice); profile switching (M3); dark-mode visual polish beyond the theme tokens.

## State Management

`store/charactersStore.ts` (Zustand, persisted list metadata only, no images): `characters[]`, `viewMode` (`carousel` | `grid`, persisted per device), loading and error state. Mutations update the store from the server response. Server is the source of truth for counts and favourites.

## Endpoints (contracts in `api/openapi/xano.yaml`, regenerated by RS-2026-11-11-01)

GET /characters?status=active|archived&name= → 200: Character[] (id, name, status, deleted_at, is_deleted, cover_image, last_modified_at, instant_stories_id, is_favourite, created_at, stories_count, picture_status: drawing | ready | failed). Archived only for a parent; favourites first.

GET /characters/{id} → 200: the list fields + physical_description. 404 if not found, not yours, deleted, or archived for a child.

POST /characters (name, physical_description) → 200: Character (as detail). 400 `NAME_NOT_ALLOWED` | `CONTENT_REJECTED`. Starts the picture in the background.

PATCH /characters/{id}/flags (status?, is_favourite?) → 200: Character (list fields). 400 `PARENT_PROFILE_REQUIRED` (child changing status) | `NOTHING_TO_UPDATE`.

DELETE /characters/{id} → 200 (soft delete). 400 `PARENT_PROFILE_REQUIRED`.

POST /characters/{id}/regenerate_image (instruction?) → 200 { status: "queued", image_jobs_id }. 400 `CONTENT_REJECTED` | `IMAGE_JOB_IN_PROGRESS`.

GET /instant_stories?characters_id= → 200: Story[] visible to the active profile.

Domain error codes are in `payload.code`; the user-facing text is `message`.

## Acceptance (Given/When/Then)

Happy path

- Given a parent with characters
- When they open Characters
- Then the carousel shows favourites first; tapping a card reveals its actions; the grid toggle shows the same characters with search and filters

Edge

- Given a character whose picture is still being drawn
- When it is shown anywhere
- Then a "Drawing [name]…" placeholder appears and is replaced by the picture without leaving the screen

Error

- Given a child profile
- When they open Characters
- Then there's no grid toggle, More, Archive or Delete; a refused name or instruction shows the server's message on the field; a network error keeps the cached list and offers retry

Device checks (Kyle, EAS dev build if a native module is added, else `pnpm start`): parent and child views on a phone; create a character and watch its picture arrive; favourite, archive, unarchive, delete; draw again with "wearing a red scarf" and with a refused instruction; carousel swipe and tap feel smooth; light and dark mode readable.
