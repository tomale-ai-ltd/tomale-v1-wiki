# OpenAI DALL·E 3  
  
## How we use it  

We use DALL·E 3 to generate all visual assets for Tomale stories, including cover images, page illustrations, and character images. Image generation is orchestrated via Xano using structured prompts derived from story and character data, with jobs processed asynchronously through the image pipeline.  
  
## Key endpoints / schema highlights  

- Core use cases:  
- Story cover images  
- Story page illustrations (typically 1 per page)  
- Character cover images  
- Pipeline integration:  
- `image_jobs` table queues all image generation tasks  
- Job types:  
- `cover-image`  
- `page-image`  
- `character-image`  
- Workers:  
- `image_worker_tick` → claims jobs  
- Executors → generate images per job type  
- Prompt structure:  
- Derived from:  
- story context (theme, plot, page text)  
- character definitions (JSON models)  
- artwork style  
- Designed to maximise consistency across pages  
- Output:  
- Images stored in S3  
- URLs written back to:  
- `instant_story_pages.image`  
- `instant_stories.cover_image`  
- `characters.cover_image`  
  
## Version / environment  

- OpenAI Images API (DALL·E 3)  
- Typical image size:  
- 1536 × 1024 (landscape stories)  
- Config controlled via:  
- `data_models.model_settings.image`  
- Environment variables:  
- API keys stored in Xano  
- Runs entirely via backend (no direct frontend calls)  
  
## Known gotchas  

- Consistency across images (same character across pages) is not guaranteed — requires strong prompt engineering.  
- Image generation is slow relative to text → must be async (jobs + workers).  
- Failures and timeouts are common enough to require retry logic.  
- Cost scales linearly per image (no batching efficiency).  
- No fine-grained control over composition — outputs can be unpredictable.
