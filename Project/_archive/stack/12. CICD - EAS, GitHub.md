# # EAS + GitHub

## Actual vs. intended usage

### Actual (evidenced in repo)

- **GitHub Actions is active**:

- PR CI to `main` runs: `npm ci`, `npm run lint --if-present`, `npm run typecheck --if-present`, `npm test -- --runInBand`.
- Push-to-`main` release workflow computes/logs release metadata.

- **EAS is configured** via `eas.json` with profiles:
- `development` (internal + dev client)
- `preview` (internal)
- `production` (auto increment)
- `submit.production` exists

- **Important current gap**:
- No committed GitHub workflow step actually running `eas build`, `eas submit`, or `eas update`.
- Security checks (`audit`, `gitleaks`, `semgrep`) are not present in current workflow files.

### Intended (documented direction)

- PR-based workflow with gated checks before merge.
- Use EAS profiles for dev/internal testing and production/store builds.
- Use GitHub + EAS secrets for CI/release automation.
- Evolve toward stronger CI/CD hardening (security scans + stricter required checks).

## Key workflow highlights

- GitHub is the source-of-truth repo and CI trigger surface.
- EAS is prepared for build/distribution but currently appears mostly **manually or externally triggered** (not fully wired in repo workflows).
- Current release workflow is metadata-oriented, not full binary build/submit automation.
- CI quality gates are partially enforced; `typecheck` may skip if script is absent.

## Version / environment

- Expo managed workflow + EAS (`cli >= 16.27.0`)
- GitHub Actions for CI/release orchestration
- Environment split represented by EAS build profiles (`development`/`preview`/`production`)
- Secrets are referenced in GitHub workflows (e.g., `EXPO_TOKEN`, Sentry vars), with additional env management expected in EAS/backend config

## Known gotchas

- “Configured” EAS does not equal “automated” EAS; builds won’t run from CI unless explicit commands are added.
- `--if-present` in CI can hide missing scripts and weaken enforcement.
- Environment drift (dev vs prod API keys/channels) can still happen without strict profile/env mapping.
- Store submission remains operationally slower and externally gated by Apple/Google review.
