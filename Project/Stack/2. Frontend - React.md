# React Native (Expo)

## How we use it

We use React Native with Expo to build a single cross-platform mobile app (iOS + Android) that powers the entire Tomale user experience, including story creation, e-reader, characters, and store flows. Expo allows us to move fast with native capabilities (TTS, orientation, media handling) without managing native code directly in V1.

## Key screens / architecture highlights

- `(tabs)/bookshelf` → core content consumption (e-reader entry point)
- `(main)/create-story/chat.tsx` → chatbot-driven story creation flow
- `(main)/characters/create.tsx` → AI-assisted character builder
- `(tabs)/store` → checkout + order history flows
- Global pattern: route-driven screens + shared components (chat UI, cards, overlays)
- Heavy use of async API calls to Xano (no local business logic duplication)

## Version / environment

- Expo: Managed workflow (`expo` `54.0.23`), with no native `ios/` or `android/` directories committed.
- EAS: Configured and active via `eas.json` (CLI `>=16.27.0`), with build profiles:
    - `development` (internal, dev client)
    - `preview` (internal)
    - `production` (store-ready, auto-increment version)
- Environment separation (dev/prod):
    - Partially configured in EAS profiles (`development` and `production` exist)
    - Not yet explicitly mapped/documented in config as `dev -> local/test backend` and `prod -> App Store/Play Store backend` (would require explicit env vars or profile-based backend URL mapping)
- Expo APIs currently in use:
    - `expo-blur` ✅ installed and imported (`BlurView` used in `components/ui/TabBarBackground.ios.tsx`)
    - `expo-speech` ❌ not installed / no usage found
    - `expo-screen-orientation` ❌ not installed / no usage found

## Known gotchas

- Expo abstractions are great until they aren’t — anything non-standard (e.g. deep native performance tuning, custom rendering pipelines) becomes painful later.
- Build/debug cycles can get messy if EAS environments aren’t tightly controlled.
- Performance bottlenecks will show up in:
  - animated lists (characters carousel)
  - page rendering (e-reader with images + text)
- You are currently relying heavily on backend orchestration — if API latency spikes, UX degrades fast.
- Offline support is minimal by design — don’t pretend it exists yet.
