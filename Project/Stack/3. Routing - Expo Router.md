# Expo Router

## How we use it

We use Expo Router to implement a file-based routing system that maps directly to the app’s feature structure (bookshelf, characters, story creation, store). It enables clear separation between `(tabs)` navigation and `(main)` stack flows, supporting both persistent tab navigation and deeper modal/flow-based screens.

## Key endpoints / schema highlights

- `(tabs)/bookshelf/[id]/read.tsx` → immersive e-reader experience
- `(main)/create-story/chat.tsx` → chatbot-driven story creation flow
- `(main)/characters/create.tsx` → character creation flow
- `(tabs)/characters/index.tsx` → character browsing experience
- `(tabs)/store/index.tsx` → store entry + checkout flow

**Routing structure pattern:**
- `(tabs)` → persistent navigation (Bookshelf, Characters, Store)
- `(main)` → transactional flows (create story, create character, checkout)
- Dynamic routes (`[id]`) used for entity-driven screens (stories, characters, orders)

## Version / environment

- Expo Router: `expo-router` `6.0.14` (SDK-aligned stable version for current `expo` `54.0.23` setup).
- Expo managed integration: Fully integrated (entrypoint is `expo-router/entry` in `package.json`, and router plugin is enabled in `app.json`).
- EAS compatibility: Works directly with existing EAS setup; no separate routing infrastructure/config is required.
- File-based route coupling: Yes—routing is defined by the `app/` directory structure (including route groups like `(main)` / `(tabs)`), so path/file changes directly affect routes; keeping that structure stable is important for CI/build consistency.

## Known gotchas

- File structure = routing logic → refactoring folders has functional impact (not just organisation).
- No strict separation between navigation and screen logic — easy to let routes become messy if not disciplined.
- Deep linking and param handling need to be explicitly tested (not implicitly guaranteed).
- Dynamic routes (`[id]`) rely on consistent backend IDs — any inconsistency in Xano responses breaks navigation.
