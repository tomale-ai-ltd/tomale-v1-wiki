# PU-2026-11-05-01: Backend rules: nullable optional inputs when false or empty is a real value

- Proposed change (§3 block, "Errors and data", after "Check for empty, not only null"): add "An optional input whose `false` or empty value means something (a flag you can turn off, a partial update) is declared nullable (`bool? x?`, `enum? x? {…}`) and checked with `!== null`. A non-nullable optional input arrives as `false` or `""` when omitted, and a loose `!= null` treats `false` as null."
- Proposed change (§6 gotchas): add "Omitted optional inputs aren't null unless declared nullable: `bool x?` arrives as `false`, `enum x?` as `""`. On 05/11 this let `{"is_favourite": false}` be refused as 'nothing to update', then (after a switch to `!==`) let every flags PATCH blank `status`. Fixed in `characters/{id}/flags` by `bool? is_favourite?` and `enum? status?`."
- The §3 block is mirrored to Xano AGENTS.md, so a re-paste is needed after approval ([[agent-context-sync]]).
