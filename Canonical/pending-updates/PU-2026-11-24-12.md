# PU-2026-11-24-12: allowed exception for lettered slices

Why: speckit's scripts only accept a three-digit branch prefix and looked up feature folders by those digits, so `010b-auth-signup` was refused and could have resolved to `specs/010-approvals`. Renaming the slice would have meant renumbering 011 onwards in the roadmap and micro-PRDs. Kyle agreed to keep the one-line fix (24/11).

- **[[operating-model]] §3.5, the "Never" row:** after the row, add: "**One allowed exception:** `.specify/scripts/bash/common.sh` accepts an optional lowercase letter after the three digits (`^[0-9]{3}[a-z]?-`) and matches feature folders on the whole prefix, so a lettered slice like `010b` never resolves to `010` (`b89c800`, 24/11). Re-apply it after any speckit upgrade (the commit message says so) and check that the prerequisites script resolves `FEATURE_DIR` on a lettered and a plain branch. Any other change to these files stays Never."
