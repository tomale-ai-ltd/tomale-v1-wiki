# PU-2026-11-20-02: app-side PIN gate rules in the security model

- Proposed change: in [[security-model]], in the **Auth** summary after "Parental PIN on every switch into a parent profile, locked after 5 wrong attempts, unlocked only by an emailed link (`purpose: reset_pin`)", add: "App side (010, 19/11): returning to the foreground can raise the profile picker but never lower it; only entering through the PIN opens a parent profile. The cold-start picker is decided once per sign-in, so a refreshed or replacement token does not raise it again ([[keep-pin-gate-closed-when-app-returns-to-foreground]]; fixes a PIN bypass where a brief background, such as the share sheet, dropped the picker over a parent token)." Why: the bypass was a security bug found on the phone; the rule should be written where reviewers check the gate, so a later navigation change can't reintroduce it.
