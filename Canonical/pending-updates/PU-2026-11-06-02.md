# PU-2026-11-06-02: Pre-launch checklist: Sentry location and a stray user_id param

- Proposed change (pre-launch checklist, observability row): Sentry events carry `user.geo` down to city (e.g. "Llangefni, Wales"), derived by Sentry from the request IP at ingestion even though the SDK sends no IP (`infer_ip: never`). Before launch, in Sentry → Settings → Projects → react-native → Security & Privacy, turn on "Prevent Storing of IP Addresses", send a test event, and if `user.geo` still appears, add an Advanced Data Scrubbing rule that removes the user's geo fields. Why: child-facing app, ICO Children's Code data minimisation.
- Proposed change (pre-launch checklist or Slice 300 note): `hooks/useBookshelf.ts` sends `?user_id=` on `GET /instant_stories`. Xano ignores it (filters on `$auth.id`), but it's a leftover that puts the account id in URLs and breadcrumbs; remove it when Slice 300 rebuilds the bookshelf.
- Observed and fine: signed-in event has `user.id` and `profile_id` (UUID) only; signed-out event has neither; no email or IP; console breadcrumbs (including a masked email) come only from the `__DEV__`-only debug logger.
