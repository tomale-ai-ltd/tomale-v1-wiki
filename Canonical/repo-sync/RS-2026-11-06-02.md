# RS-2026-11-06-02: Call auth/logout when the parent signs out

- Change: on a user-initiated sign-out, first call `POST /auth/logout` with `{ session_id }` from the store (published in Xano 06/11; always returns `{success: true}`; sets the session to `revoked`, so `auth/refresh` then returns 401). Best effort: whatever the result (including network errors or a 401 from an expired access token), clear the local session as today. Skip the call when no `session_id` is stored. Do not call it on the automatic sign-out after a rejected refresh. The URL contains `/auth/`, so the interceptor must not try to refresh on its failure (already the rule).
- Speckit impact: none (small follow-up to 007)
- Process: edit, with a Jest test (logout called with session_id; local sign-out still happens when it fails)
- Verify: tests and CI green; on a device, sign out then reuse the old refresh token in Postman: 401 `invalid_refresh_token`

- Applied: `main` 3f14585 (PR #24, rebase-merged 06/11). Backend check in Postman 06/11: 1F logout 200, then refresh 401 `invalid_refresh_token`; added to `_tests` as 1F and 1G.
