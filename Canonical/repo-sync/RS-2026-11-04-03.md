# RS-2026-11-04-03: Cursor permissions: repo allowlist and deny hooks

- Change: commit repo-level Cursor permissions so routine, local, read-only or reversible commands run without prompts, everything else asks, and a few actions are hard-blocked.
  - `.cursor/permissions.json` → `terminalAllowlist` (exact prefixes, never bare `git`/`pnpm`/`npx`/`gh`): `git status`, `git diff`, `git log`, `git show`, `git fetch`, `git rev-parse`, `git add`, `git commit`, `git switch`, `git checkout -b`, `git branch --show-current`, `git branch -a`, `git branch --list`, `pnpm typecheck`, `pnpm test`, `pnpm lint`, `pnpm audit`, `pnpm install --frozen-lockfile`, `npx expo-doctor`, `npx expo config`, `rg`, `ls`, `cat`, `node -v`, `gh pr view`, `gh pr checks`, `gh pr list`, `gh run view`, `gh run list`, plus the speckit and helper scripts Cursor already uses: `.specify/scripts/bash/`, `.specify/extensions/git/scripts/bash/create-new-feature.sh`, `./scripts/setup-doctor.sh`, and harmless shell basics `pwd`, `head`, `tail`, `wc`, `which`, `mkdir`, `nvm use`, `node -v`, `pnpm -v`. **No `mcpAllowlist` key** (a key in the repo file replaces the Settings list, and the Settings MCP list holds the machine-specific simulator entry). No `autoRun` block (Run Mode stays Allowlist, not Auto-review). Note: once this file defines `terminalAllowlist`, it replaces the Settings command list for this repo, which removes the over-broad Settings entries (`git push`, `python3`, `node`, `.`, `command`, `cd`, `set`, `npm install`, `pnpm install`).
  - Everything else asks (Allowlist mode), including `git push` (with or without `--force-with-lease`), `gh pr create`, `pnpm add`, non-frozen `pnpm install`, `npx expo install`, `eas build`, `rm`, `curl`, `git reset`, `git rebase`, plain `git checkout` (it can discard changes).
  - `.cursor/hooks.json` → `beforeShellExecution` running `.cursor/hooks/guard.sh` with `failClosed: true`. The script returns `deny` (with a short user message) for: `gh pr merge`; `git push` with `--force` or `-f` but not `--force-with-lease`; any push to `main` (`git push … main`, `HEAD:main`); `eas submit`; `eas update`; `git push --delete` / `git push … :branch`. Everything else returns no decision (the allowlist and Run Mode decide). Follow the current Cursor hooks docs for the input and output JSON.
- Speckit impact: none
- Process: edit, standalone PR `repo-sync/YYYY-MM-DD-cursor-permissions`; Kyle sets Settings → Agents → Approvals & Execution → Run Mode to Allowlist
- Verify: in a Cursor chat, `git status` runs without a prompt; `pnpm add left-pad` asks; `gh pr merge 1` and `git push --force origin x` are denied by the hook with the message; the hook denies even if a command were on the allowlist (test with a throwaway local allowlist entry, then remove it); CI `test` green
