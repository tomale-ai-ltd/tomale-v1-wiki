# RS-2026-11-12-03: Cursor rule for UI work

Add `.cursor/rules/ui.mdc` (auto-attached to `app/**` and `components/**`), short. It is a working guide that applies the constitution (Principles 2 and 4) to screens; it adds no new principles or quality gates, and opens with: "The constitution governs; if this file ever conflicts with it, follow the constitution and flag the conflict." Rules:

- **Design source:** the feature's `specs/<feature>/design/` (PNG = visual target, `.dc.html` = exact values). Map values to theme tokens; never hard-code hex, font sizes or spacing.
- **Build from the kit:** use the shared components in `components/ui/` (card, action tile, sheet, toast, pressable, button). Add to the kit rather than styling one-off in a screen.
- **States:** every tappable has a pressed state; server-bound actions show a loading state and ignore repeat taps; optimistic actions update at once and roll back on refusal; empty, loading, error and offline states for every list.
- **Confirmations** are toasts above the tab bar, auto-dismissing (~3 s) and announced; never inline in the page.
- **Layout:** safe areas on every screen; 48-point minimum tap targets; spacing from the token scale; type from the theme text components (scales with the device setting).
- **Pictures:** character and story images never crop heads or faces; follow the mock-up framing.
- **Motion:** short (150–250 ms), respects Reduce Motion.
- **Light and dark:** check both.
- **Done means seen:** after a UI change, run `pnpm shot` (RS-2026-11-12-02), compare with the mock-up, fix, and include the screenshot pair when reporting.

- Speckit impact: applies to every UI task from 008 US6 on. If Kyle wants "done means seen" to be a formal quality gate, that is a separate class A constitution amendment.
- Verify: rule file present, glob set, under ~60 lines.
